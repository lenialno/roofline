# Протокол бенча

## Перед прогоном

- Сервер прогрет: 1-2 минуты запросов или один `task bench BENCH_N=8`
- Никто другой не грузит GPU: `task gpu`
- Записаны версия движка, профиль, GPU, драйвер, `task metrics` до прогона

## Матрица

| Что меняем | Фиксируем | Прогоны |
|---|---|---|
| конкурентность | модель, флаги | C = 1, 4, 8, 16, 32 при IN=2048, OUT=256 |
| длина промпта | C = 8 | IN = 512, 2048, 8192, 32768 |
| квантование | C = 8, IN = 2048 | bf16, FP8, FP8 + fp8 KV, AWQ |
| TP | C = 8 | TP = 1, 2, 4 при одинаковой модели |
| спекуляция | C = 1, 4, 8 | без, n-gram, EAGLE3 |

Одна переменная за прогон. Каждый прогон минимум N = 4 x C запросов.

## Чтение результата

- Решение по p95; p50 только для сравнения с прошлым прогоном
- Общий tok/s растёт с C до насыщения; точка, где TPOT p95 выходит за SLO, это рабочий максимум `max-num-seqs`
- TTFT растёт с C при полном KV: смотреть `waiting` и `preemptions` в `task metrics` после прогона
- Ошибки больше 0: результат недействителен, сначала причина

## Запись в журнал

```
дата | профиль | движок/версия | GPU x N, TP | IN/OUT | C | ttft p95 | tpot p95 | tok/s | вердикт | что меняли
```

`task bench -- --json` печатает ещё и строку JSON с теми же полями.
