# Теория для инженера: выжимка из книги Буркова

Источник: Андрей Бурков, "Языковые модели без лишних слов. Практика на PyTorch", БХВ-Петербург, 2026, 208 с. Здесь только то, что меняет решения в serving; страницы книжные. Книга в продаже: [Ozon](https://www.ozon.ru/product/yazykovye-modeli-bez-lishnih-slov-burkov-andrey-4678629427/?at=1iao1Xu0NlUIcfcFRZUKWGxeT6SFLpfc&sh=YcvAR88O_Q).

| Факт из книги | Страницы | Что это значит для serving |
|---|---|---|
| KV-кеш: после обучения матрицы K и V фиксированы, ключи и значения старых токенов не меняются, их считают один раз и хранят. Для нового токена считают только его K и V и добавляют в кеш. RoPE кешированию не мешает: поворот применяется только к новому токену в позиции L+1 | 140-141 | KV-кеш это память, а не вычисления: размер растёт линейно с длиной контекста и числом параллельных запросов. Бюджет считает `task vram` |
| Обычное попарное внимание растёт квадратично с длиной последовательности; длинный контекст дорог | 149-159 | prefill длинных промптов (Claude Code: 20-100k токенов) compute-bound; лечится prefix cache и chunked prefill, не квантованием |
| Формат ролей и границ ответа обязан совпадать с форматом обучения. ChatML: `<\|im_start\|>role`, текст, `<\|im_end\|>`; роли system, user, assistant. Одна функция сборки промпта и для обучения, и для инференса | 164-170 | chat template в tokenizer_config.json это контракт модели. Чужой или урезанный шаблон ломает tool calling раньше любого парсера |
| Выборка: температура делит логиты, top-k оставляет k кандидатов, top-p минимальный набор с суммой не меньше p, штрафы за частоту и присутствие снижают логиты повторов. Снижение случайности не проверяет факты | 174-179 | температура 0 для бенчей и smoke-тестов (воспроизводимость); спекулятивное декодирование теряет acceptance rate при высокой температуре |
| Перплексия: экспонента средней потери на реальных токенах; меньше лучше; сравнивать только на одинаковых данных и токенизации | 85-89 | PPL до и после квантования на своём тексте. Рост больше 1-2% это сигнал, а не шум |
| LoRA: базовые веса заморожены, учится низкоранговая поправка, базовая модель остаётся в памяти | 179-183 | много LoRA на одной базе: роутить запрос к реплике, где адаптер уже загружен (roadmap: LoRA-aware routing) |
| MoE активирует часть экспертов на токен | 199 | в батче активны почти все эксперты: память под веса считать полностью, выигрыш только в compute на один запрос |
| Сжатие: квантование, прореживание, дистилляция | 200 | квантование единственное, что делает инженер serving; дистилляция это заказ ML-команде |
| Джейлбрейк обходит ограничения модели, prompt injection вставляет команды через внешние данные | 201-202 | tool-calling агент исполняет инъекции из результатов инструментов; защита на стороне клиента и прокси, не движка |
| Настройка на инструкции не гарантирует правильность фактов; объяснение модели не доказывает, как получен ответ | 155, 192 | evals и smoke-тесты проверяют поведение, не ответы модели о себе |
